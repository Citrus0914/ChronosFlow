## 📌 会话交接记录 [2026-10-29 10:42]

### 🎯 本次任务目标
- 深度排查并修复 `【双击启动ChronosFlow】.bat` 双击报错无法启动的故障。

### 🐞 修复的问题与缺陷 (Bug Fixes)
- **问题现象**：双击启动脚本时，Windows 控制台报错 `'s' is not recognized`、`'rg'`、`'px'`、`'vel'` 等奇怪命令并直接退出。
- **根本原因排查**：
  1. **CRLF 换行缺失**：原脚本文件由 Linux/Unix 默认 LF（`\n`）保存，Windows `cmd.exe` 在解析包含中文字符与 UTF-8 编码的脚本时，因缺少 `\r` 导致缓冲区寻址偏移量计算错乱，截断了变量名与命令（例如 `%errorlevel%` 截断成 `vel`、`https://nodejs.org` 截断成 `rg`）；
  2. **缺少 call 关键字**：`pnpm` 在 Windows 下为 `pnpm.cmd`，作为子批处理脚本被调用时若未前缀 `call`，执行后会直接退出父进程。
- **解决方案**：
  1. 重建脚本并使用严格 Windows 标准 CRLF（`\r\n`）行尾序列与 UTF-8 编码写入；
  2. 移除 4 字节 Unicode Emoji，避免控制台列宽计算偏差；
  3. 为 `call %RUNNER% install` 与 `call %RUNNER% run dev --open` 显式添加 `call` 前缀。

### 📁 涉及的核心文件与代码变更 (Changes)
- `【双击启动ChronosFlow】.bat`: 规范换行符为 CRLF 并增加 `call` 调用。
- `启动.bat`: 同步规范换行与调用。

### ⚠️ 关键决策与避坑提示 (Decisions & Gotchas)
- **Windows Batch 铁律**：所有面向用户双击执行的 `.bat` 批处理脚本，**必须使用标准 CRLF 换行符保存**。任何 LF 换行的 UTF-8 批处理文件在包含中文时，都会被 Windows `cmd.exe` 灾难性截断。

### 🐞 修复的问题与缺陷 (Bug Fixes)
- **顶部与底部重叠问题**：
  - **根本原因**：安卓沉浸式模式下（`setDecorFitsSystemWindows(false)`），WebView 默认绘制在全屏坐标系；而标准 Android WebView 不会自动向 CSS 暴露 `env(safe-area-inset-*)`，且在三星 One UI 系统中，3 键虚拟导航栏在部分配置下返回 `visible=false`，常规 `systemBars()` 探测得到 0。
  - **解法**：
    1. 在 `MainActivity.kt` 中综合探测 `systemBars`、`systemBarsIgnored`、`tappableElement`、`mandatorySystemGestures` 以及底层 `dimen/navigation_bar_height` 与 `dimen/status_bar_height`，精准获取状态栏（~27dp）与导航栏（~48dp）；
    2. 通过 `@JavascriptInterface` 与全局 CSS 变量实时注入 `--safe-top` 与 `--safe-bottom`；
    3. `Header` 增加 `paddingTop: calc(0.75rem + var(--safe-top, 0px))`，安全避让状态栏与挖孔摄像头；
    4. `TabBar` 增加 `paddingBottom: max(var(--safe-bottom, 0px), 8px)`，背景无缝沉浸延伸至底边，按键与文字精准悬停在虚拟返回/Home键上方。
- **底边留白过多问题**：
  - **根本原因**：页面主容器 `<main>` 此前设置了过大的 `6.5rem` 内边距，且各个 Tab 卡片内部也残留了 `pb-20` / `pb-4`，导致滚动到底部时留下过大的空白区域。
  - **解法**：移除各 Tab 视图的多余内边距，并将 `<main>` 的底部内边距精确收敛为 `calc(3.8rem + var(--safe-bottom, 0px))`，保证最后一个卡片距离 TabBar 仅保留精细的 ~12px 呼吸间距，杜绝多余空白。
